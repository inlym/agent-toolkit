# 日志规范

不限定编程语言，按项目所用日志框架的标准方式落地。

## 日志级别

**系统生命周期**：

- `INFO`：启动、初始化、配置加载
- `WARN`：使用默认配置、功能降级
- `ERROR`：阻止应用运行的错误

**用户请求**：

- `TRACE`：每次请求都执行的操作（方法进出、参数）
- `DEBUG`：条件触发的操作（缓存命中、分支）
- `INFO`：重要业务操作（第三方 API 调用、金融交易）
- `WARN`：不影响请求完成的潜在问题
- `ERROR`：阻止正常响应的错误

## 使用规范

- 通过项目日志框架的标准方式获取 logger，不自行实现输出逻辑
- 使用参数化/结构化日志，禁止字符串拼接
- 记录异常时传入异常对象本身（而非仅错误消息），以保留堆栈信息
- 禁止记录敏感信息（密码、信用卡、API 密钥）
- 系统级异常由全局异常处理机制统一记录 ERROR 日志，业务异常不记录日志
- 方法未执行完整逻辑而提前退出时，必须在退出语句上方打一条 `TRACE` 日志，说明跳过的原因

```text
✅ 正确：void 方法
if (user == null) {
    log.trace("用户不存在，跳过通知，userId={}", userId)
    return
}

✅ 正确：有返回值方法
if (cache != null) {
    log.trace("命中缓存，直接返回, key={}", key)
    return cache
}

❌ 错误：无日志直接提前退出
if (user == null) {
    return
}
```
